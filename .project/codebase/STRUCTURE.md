## Directory Purposes

**`goed/`** — The deployed Vue 3 SPA. Netlify builds from here (`base = "goed/"` in `netlify.toml`). All client-side code lives under `goed/src/`. Both products (Founder's Navigator + Utah Startup Map) ship as routes within this single app.

**`goed/src/components/`** — Reusable Vue SFCs grouped by feature subdirectory, never flat. Subdirectories: `map/`, `drawer/`, `filters/`, `submit/`. Add a new subdirectory when introducing a new feature surface.

**`goed/src/views/`** — Page-level components mounted by the router. Top-level files map to top-level routes; nested folders (e.g. `admin/`) mirror nested URL paths.

**`goed/src/router/`** — Single `index.js` exporting the router instance. Route guards live in sibling `guards.js` and are imported into route definitions via `beforeEnter`.

**`goed/src/stores/`** — Pinia stores written in composition-API style (`defineStore('name', () => { … })`). One file per domain (`admin.js`, `startups.js`, `filters.js`).

**`goed/src/composables/`** — Reusable reactive hooks. File naming: `useXxx.js`. Examples: `useAdminAuth.js`, `useOnboarding.js`, `useLogoDev.js`.

**`goed/src/lib/`** — Pure or third-party-client wrappers shared across the app. Examples: `supabase.js` (client singleton), `clusterStyle.js` (OpenLayers style helper).

**`goed/src/styles/`** — Global CSS only. Currently just `brand.css` containing `@tailwind base/components/utilities` directives.

**`goed/scripts/`** — Local one-off Node scripts (e.g. `import-seed-companies.js`). Not part of the Vite build. Can produce log files (`*.log`) committed only if intentional.

**`supabase/migrations/`** — SQL migrations applied via Supabase CLI. Numbered `NNNN_descriptor.sql` (zero-padded 4 digits). Sequential — do not rename or renumber.

**`supabase/functions/`** — Deno edge functions, one directory per function. The directory name is the deployed function name. Each contains an `index.js` entry plus optional helpers in the same folder.

**`supabase/functions/_shared/`** — Modules imported across multiple edge functions. Subfolder `enrichers/` holds per-source data enrichers (`github.js`, `crunchbase.js`, `news.js`, `producthunt.js`, `utah-dcc.js`, `wappalyzer.js`).

**`scripts/`** — Repo-root automation. Shell scripts only; node scripts belong under `goed/scripts/`.

**`.project/`** — SPEC workflow state (committed). `epics/` are large planning docs, `features/NNNN/` track incremental work with `ROADMAP.md`, `STATE.md`, and `phases/phase-N/` (`PLAN.md`, `VERIFICATION.md`).

**`.claude/`** — Claude Code config and worktrees. Entirely gitignored.

## Naming Conventions

**Files:**
- Vue components: `PascalCase.vue` (e.g. `UtahMap.vue`, `CompanyDrawer.vue`, `AdminLogin.vue`)
- JS modules: `camelCase.js` (e.g. `useAdminAuth.js`, `clusterStyle.js`, `supabaseAdmin.js`)
- Composables: must start with `use` (e.g. `useOnboarding.js`)
- Pinia stores: short noun, lowercase (e.g. `admin.js`, `startups.js`, `filters.js`)
- Edge function helpers: `kebab-case.js` (e.g. `google-places.js`, `logo-dev.js`, `utah-bounds.js`, `quality-gate.js`)
- SQL migrations: `NNNN_snake_case.sql` (zero-padded number, underscore-separated)
- SPEC docs: `UPPERCASE.md` (e.g. `ROADMAP.md`, `STATE.md`, `PLAN.md`, `VERIFICATION.md`)

**Directories:**
- Component groups under `components/`: lowercase single word (`map`, `drawer`, `filters`, `submit`)
- View groups: lowercase (`admin/`)
- Edge functions: `kebab-case` (`onboard-company`, `refresh-jobs`)
- Shared edge-function modules: prefix with underscore (`_shared/`)
- Feature folders: zero-padded number (`0001`, `0002`, `0003`, `0004`, `0005`)
- Epic folders: number + slug (`0001-utah-startup-map`)
- Phase folders: `phase-N` (1-indexed, no padding)

**Routes / store IDs:**
- URL paths: lowercase, single-segment (`/map`, `/navigator`, `/submit`, `/admin/dashboard`)
- Route names: `PascalCase` (`Map`, `Navigator`, `AdminLogin`, `AdminDashboard`)
- Pinia store IDs: lowercase string matching filename (`'admin'`, `'startups'`, `'filters'`)

## Where to Add New Code

**New page / route:**
- View component: `goed/src/views/YourView.vue` (or `goed/src/views/section/YourView.vue` for nested URLs)
- Register in `goed/src/router/index.js` with lazy import: `() => import('@/views/YourView.vue')`
- Add `RouterLink` in `goed/src/App.vue` nav if user-facing
- Add `beforeEnter` guard from `goed/src/router/guards.js` if access-controlled

**New feature surface (e.g. analytics, dashboard widget):**
- Create folder: `goed/src/components/<feature>/`
- Components inside: `goed/src/components/<feature>/MyComponent.vue`
- Domain store (if stateful): `goed/src/stores/<feature>.js`
- Composables (if reusable logic): `goed/src/composables/use<Feature>.js`

**New component within an existing feature:**
- Drop into the matching folder: `goed/src/components/map/NewLayer.vue`, `goed/src/components/filters/NewFilter.vue`, etc.

**New shared utility / helper:**
- Pure JS or third-party wrapper: `goed/src/lib/<name>.js`
- Reactive hook: `goed/src/composables/use<Name>.js`

**New Pinia store:**
- File: `goed/src/stores/<domain>.js`
- Pattern: composition-API style — `export const use<Domain>Store = defineStore('<domain>', () => { … })`

**New global style:**
- Add to `goed/src/styles/brand.css` only if Tailwind utility classes can't express it
- Prefer Tailwind classes inline in templates; extend the theme via `goed/tailwind.config.js`

**New edge function:**
- Folder: `supabase/functions/<kebab-name>/`
- Entry: `supabase/functions/<kebab-name>/index.js`
- Function-local helpers: same folder
- Cross-function helpers: `supabase/functions/_shared/`
- New data source enricher: `supabase/functions/_shared/enrichers/<source>.js`

**New database change:**
- New migration file: `supabase/migrations/NNNN_descriptor.sql` (next sequential number)
- Never edit prior migrations — append a new one

**New repo-level automation script:**
- Shell: `scripts/<name>.sh`
- Node one-off (uses `goed/` deps): `goed/scripts/<name>.js`

**New SPEC feature:**
- `.project/features/NNNN/ROADMAP.md` and `STATE.md`
- Phase work: `.project/features/NNNN/phases/phase-N/PLAN.md` and `VERIFICATION.md`
