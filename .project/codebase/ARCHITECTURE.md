## Data Flow

**Founder's Navigator — AI Search Flow (per `FOUNDERS_NAVIGATOR.md` lines 64–79):**

1. User completes 6-step intake wizard at `/navigator` (Vue components, GSAP transitions between steps)
2. `useIntakeStore` accumulates structured fields (stage, industries[], communities[], locations[], topics[], free-text description)
3. On submit, frontend calls `supabase.functions.invoke('search-resources', { body: intakePayload })`
4. `search-resources` Edge Function:
   - Embeds free-text description via OpenAI/Claude embedding API → 1536-dim vector
   - Runs hybrid query on `resources` table:
     - Deterministic SQL filter: `WHERE communities && $communities AND industries && $industries AND topics && $topics`
     - pgvector cosine similarity: `ORDER BY embedding <=> $query_embedding`
   - Combines scores → returns top 10–15 candidates
5. Frontend calls `supabase.functions.invoke('generate-next-steps', { body: { intake, candidates } })`
6. `generate-next-steps` Edge Function:
   - Sends intake + candidates to Claude with reranking prompt
   - Claude returns top 5 reranked resources with "why this matched" explanations + markdown next-steps guide
7. Frontend renders results page: GSAP stagger entrance on resource cards, expandable "why matched" tooltip, next-steps markdown section, contact card placeholder
8. (Stretch) Frontend matches user topics/communities → `contacts` table → recommends GOED staff contact

**Startup Map — AI Enrichment Pipeline (one-time import, per `STARTUP_MAP.md` lines 18–22, 84–88):**

1. Operator (developer) reads 96 startups from Google Sheet (`docs.google.com/spreadsheets/d/1D9CUtXpyPubOkt51wD9SDCpglkQv6W6oa33iTs73cCk`)
2. For each row:
   - Geocode `Full Address` → lat/lng via Nominatim (free, no API key); fall back to Google Maps Geocoding for low-confidence Utah addresses
   - Fetch logo URL from logo.dev: `https://img.logo.dev/{domain}?token={LOGO_DEV_TOKEN}` (stored as `logo_url` in DB)
3. Insert enriched row into `startups` table with `verified: true`
4. `embedding` is not used for Map — filters are deterministic and client-side

**Startup Map — Read Flow (runtime):**

1. User loads `/map` → `useStartupsStore` calls `supabase.from('startups').select('*')` once on mount
2. All 96 rows held in Pinia store memory
3. Filter sidebar mutates Pinia filter state → computed `filteredStartups` re-runs → OpenLayers vector source re-renders pins reactively
4. User clicks pin → `ol-interaction-select` fires → store sets `selectedStartup` → drawer slides in (GSAP) showing logo, name, sector, stage, employee range, description, website/LinkedIn, hiring badge, job postings

**Startup Map — Self-Service Submission Flow (per `STARTUP_MAP.md` lines 128–136):**

1. User clicks "Add your startup" CTA on `/map`
2. Submission form captures all profile fields
3. Frontend calls `supabase.functions.invoke('geocode-submission', { body: profile })`
4. Edge Function geocodes address → inserts into `startup_submissions` with `status: 'pending'` and `startup_data jsonb` payload
5. GOED staff review via Supabase table editor → change `status` to `approved`
6. (Optional trigger) Approved row is moved/copied into `startups` table
7. (Stretch) Email confirmation sent to submitter

**State Management:**
- Pinia stores wrap Supabase queries (one store per domain entity — resources, startups, intake)
- Components read via `storeToRefs(store)` (no manual reactivity glue)
- Filter state is reactive computed → triggers map re-renders without explicit subscriptions
- Wizard state persists across step components via `useIntakeStore` so back/forward navigation preserves entries

## Authentication & Admin Patterns

**Public access (current scope):**
- All read access (resources, startups) is public via Supabase anon key
- Submissions to `startup_submissions` are public writes (no auth required for the "Add your startup" form)
- Row Level Security (RLS) policies should restrict: anon can SELECT from `resources` and `startups`, INSERT into `startup_submissions`; cannot UPDATE/DELETE

**Admin access (GOED staff):**
- Uses Supabase dashboard table editor directly — no custom admin UI in scope
- GOED staff log into Supabase project → edit `resources`, `startups`, review `startup_submissions`
- Trigger on `resources` row update auto-regenerates embeddings (no developer intervention)
- Approving submissions: change `startup_submissions.status` from `pending` → `approved`; trigger or manual move into `startups` table

**Future auth (out of hackathon scope, per `FOUNDERS_NAVIGATOR.md` line 122):**
- Google OAuth via Supabase Auth
- Saves user search history and personalized recommendations
- `useAuthStore` Pinia store would wrap `supabase.auth` session/state

## Cross-Cutting Concerns

**Error Handling:**
- Strategy: Try/catch around every `supabase.functions.invoke()` and `supabase.from()` call in Pinia store actions
- User-facing: Display friendly error toast/banner; never surface raw Supabase/Postgres errors
- Edge Functions: **Always return `{ error: string, code: number }` on failure.** Every Edge Function must implement this shape consistently — frontend stores parse it and set the `error` ref.
- Specific failure modes to handle:
  - Embedding service down → return SQL-only results with degraded ranking
  - Claude reranking fails → fall back to raw pgvector top 5 with generic next-steps copy
  - Geocoding fails → store address, mark `lat/lng` null, GOED staff manually fix in table editor

**Loading States:**
- Pattern: Each Pinia store exposes `isLoading: ref(false)` toggled in action begin/end
- UI: Skeleton placeholders for Navigator results cards, spinner overlay for Map initial load, inline spinner for wizard submit button
- GSAP: Entrance animations chained AFTER loading completes (do not animate skeleton → real content swap)

**Logging:**
- Frontend: `console.error` only for unexpected failures; no logging framework needed for hackathon
- Edge Functions: Supabase function logs (built-in) capture stdout/stderr from Deno runtime
- No analytics in initial scope

**Validation:**
- Frontend: Wizard step validation before allowing "Next" (required fields per step)
- Edge Functions: Defensive validation of incoming payload shapes; reject malformed requests with 400
- Database: NOT NULL constraints on `name`, `id`; check constraints on enum-like text columns (sector, stage, employee_range)

**Animations (cross-cutting GSAP usage):**
- Landing: card entrance stagger
- Navigator wizard: slide/fade between steps
- Navigator results: stagger entrance on resource cards
- Map drawer: slide-in from right on pin select
- **Rule:** Simple, one-off GSAP animations (e.g., a single `gsap.to()` for drawer open/close) can be written inline in the component's `onMounted`/handler. Extract to a composable only when the animation is complex or reused across multiple components.

**Styling (cross-cutting):**
- Tailwind CSS (to be installed) — utility-first
- Brand color: Utah blue `#0065A4` + white (matches startup.utah.gov)
- Configure brand color as Tailwind theme extension; reuse via `bg-utah-blue` etc.

**Environment Configuration:**
- `.env` (gitignored) holds `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
- Edge Function secrets (Anthropic, OpenAI, Google Maps API keys) configured via Supabase dashboard / CLI — never bundled into frontend
- Vite exposes only `VITE_*`-prefixed env vars to client bundle (security boundary)

## Database Schema

**Navigator tables (per `FOUNDERS_NAVIGATOR.md` lines 36–61):**

```sql
-- Resources table (100 rows imported from Google Sheet)
create table resources (
  id bigint primary key,
  title text not null,
  description text,
  communities text[],        -- Student / Women / Veteran / Multicultural / New American / Rural / Any
  industries text[],         -- Aerospace / Agriculture / Arts / CPG / Financial / Hospitality / Life Sciences / Manufacturing / Software / Other
  locations text[],          -- Utah regions/cities
  topics text[],             -- Funding / Start a Business / Late Stage Growth / Marketing and Sales / International Trade / Close or Exit / Relocate / Taxes and Finance / Other
  link text,
  email text,
  embedding vector(1536)     -- pgvector, auto-generated via trigger on UPDATE
);

-- GOED contacts table (data not yet sourced; build later stage)
create table contacts (
  id bigint primary key generated always as identity,
  name text,
  role text,
  email text,
  topics text[],             -- maps to resource Topics for matching
  communities text[]         -- maps to resource Communities for matching
);
```

**Map tables (per `STARTUP_MAP.md` lines 53–82):**

```sql
-- Startups table (96 rows imported + verified, plus approved submissions)
create table startups (
  id uuid primary key,
  name text not null,
  description text,
  website text,
  linkedin text,
  address text,
  city text,
  lat numeric,               -- geocoded from address (Nominatim/Google)
  lng numeric,               -- geocoded from address
  region text,               -- SLC / Utah Valley / Ogden/Weber / St. George / Cache Valley / Other Utah
  sector text,               -- B2B Software / FinTech / Security / Energy / Bio-Medical Tech / Consumer / Marketplaces
  stage text,                -- Seed / Series A / Series B
  funding_stage text,
  business_type text,
  employee_range text,       -- 1-10 / 11-50 / 51-200 / 201+
  founded_year int,          -- use founded_year (not year_founded)
  is_hiring boolean,
  job_titles text[],         -- use job_titles (not job_postings)
  careers_url text,
  logo_url text,             -- precomputed at import from logo.dev
  google_place_id text,
  google_rating numeric,
  phone text,
  verified boolean default true,
  last_refreshed_at timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- Pending submissions queue (unverified self-service)
create table startup_submissions (
  id bigint primary key generated always as identity,
  startup_data jsonb,        -- full profile as submitted (denormalized blob)
  status text default 'pending',   -- pending / approved / rejected
  submitted_at timestamptz default now()
);
```

**Schema design notes:**
- `text[]` arrays (instead of join tables) on `resources` for fast `&&` overlap filtering — simpler queries, acceptable since values are constrained enums managed by GOED staff
- `embedding vector(1536)` matches OpenAI `text-embedding-3-small` / `ada-002` / Claude embedding dimensions
- `startup_submissions.startup_data jsonb` is intentionally denormalized — submissions are quarantine data, only structured into `startups` columns on approval
- `verified boolean` on `startups` distinguishes imported (trusted) vs. submitted-and-approved (reviewed)
- `created_at timestamptz default now()` audit column on submission/insert tables

**Indexes (intended):**
- HNSW or IVFFlat index on `resources.embedding` for fast cosine similarity
- GIN indexes on `resources.communities`, `resources.industries`, `resources.topics` for `&&` array overlap
- B-tree on `startups.sector`, `startups.stage` if filter performance becomes an issue (96 rows likely doesn't need it)

**Row Level Security (intended):**
- `resources`: anon SELECT allowed; UPDATE/INSERT restricted to authenticated GOED staff
- `startups`: anon SELECT allowed; INSERT/UPDATE restricted
- `startup_submissions`: anon INSERT allowed (submission form); SELECT/UPDATE restricted to staff
- `contacts`: anon SELECT allowed; UPDATE restricted
