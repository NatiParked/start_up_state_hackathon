# Architecture Overview

## System Type

**Overall:** Two-tier serverless web application — Vue 3 SPA frontend + Supabase backend (Postgres + Edge Functions). Single-product (Utah Startup Map) with a clear `map_*` namespace convention. Not a monorepo; a single Vite app in `goed/` plus a sibling `supabase/` directory of edge functions and migrations.

**Key Characteristics:**
- **JavaScript-only, no TypeScript** — all source files are `.js`/`.vue`. JSDoc is used for type contracts.
- **Serverless backend** — no long-running server. All backend logic lives in Supabase Edge Functions (Deno runtime) under `supabase/functions/`.
- **Database-as-API** — the Vue client talks directly to Postgres tables via the Supabase JS client; RLS policies enforce who can read/write what.
- **Public read / public submit / admin-gated review** — three distinct security boundaries enforced at the RLS layer.
- **Allow-list admin auth** — Supabase magic-link OTP plus a `map_admin_users` allow-list table, checked in both client guard and DB RLS.
- **All schema changes are manual SQL migrations** — files in `supabase/migrations/` are applied via `supabase db push` or the Supabase MCP tool `apply_migration`, never auto-run.
- **Data enrichment is AI-augmented** — Google Gemini 2.0 Flash performs gap-fill on scraped/enricher output inside the `onboard-company` Edge Function.

## Layers

**Frontend Presentation Layer (Vue Components):**
- Purpose: Render UI, capture user input, dispatch to stores/composables. No direct Supabase calls except via composables.
- Location: `goed/src/views/`, `goed/src/components/`
- Contains: `.vue` Single-File Components grouped by feature area (`components/map/`, `components/filters/`, `components/drawer/`, `components/submit/`).
- Depends on: stores, composables, router.
- Used by: Vue Router (top-level views) and parent components (sub-components).
- Top-level shell: `goed/src/App.vue` (renders `<RouterView />` under a hard-coded nav bar).

**Routing Layer:**
- Purpose: Map URL paths to view components and enforce admin auth on `/admin/dashboard`.
- Location: `goed/src/router/index.js`, `goed/src/router/guards.js`
- Pattern: Lazy-loaded route components via dynamic `import()`. The `adminGuard` is wired through `beforeEnter` on the dashboard route only — `/admin` is a redirect to `/admin/dashboard`.

**State Layer (Pinia Stores):**
- Purpose: Cross-component reactive state and the only place that writes to / reads from Supabase tables.
- Location: `goed/src/stores/`
- Stores:
  - `goed/src/stores/startups.js` — `useStartupsStore` — fetches `map_startups`, holds `companies`, `selectedCompany`, computes `filteredCompanies` by combining with `useFiltersStore`.
  - `goed/src/stores/filters.js` — `useFiltersStore` — 9 filter dimensions (sectors, stages, regions, investors, etc.), all client-side filtering on a small dataset.
  - `goed/src/stores/admin.js` — `useAdminStore` — admin session + submission queue (`map_startup_submissions`).
- Pattern: Composition-style `defineStore('name', () => { … })` with `ref` state and exposed actions.

**Composables Layer (Reactive Helpers):**
- Purpose: Reusable reactive logic that doesn't belong in a store. Wraps async calls and exposes `ref` state.
- Location: `goed/src/composables/`
- Composables:
  - `useAdminAuth.js` — module-level Supabase auth subscription, `signInWithMagicLink`, `signOut`, `isAdmin` (verified against `map_admin_users`).
  - `useOnboarding.js` — wraps `supabase.functions.invoke('onboard-company', …)` with status/result/error refs and an `MIN_RUNNING_MS` minimum-display delay.
  - `useLogoDev.js` — domain-memoized logo URL builder for the logo.dev CDN.

**Backend Service Layer (Supabase Edge Functions, Deno):**
- Purpose: Serverless HTTP endpoints for orchestration, AI calls, and any logic needing service-role DB access.
- Location: `supabase/functions/`
- Functions:
  - `supabase/functions/onboard-company/index.js` — Public POST endpoint. Parses + validates `{ url, email? }`, runs the enrichment pipeline, applies the quality gate, then either inserts into `map_startups` (auto-publish) or `map_startup_submissions` (pending). Always inserts an audit row into submissions.
  - `supabase/functions/refresh-jobs/index.js` — Service-role POST endpoint. Bulk mode (cron) re-polls ATS for any startup with `jobs_refreshed_at` older than 7 days; single-company mode supports forced refresh from admin tooling. Writes one row per run to `refresh_log`.

**Backend Domain Logic (`_shared`):**
- Purpose: Pure-logic modules shared across edge functions. Pipeline orchestration, source enrichers, and infrastructure clients.
- Location: `supabase/functions/_shared/`
- Modules:
  - `pipeline.js` — `runEnrichmentPipeline({ url, email })`: 9-step orchestration (fetch HTML → logo → parallel enrichers → ATS → LLM gap-fill → geocode → normalized record).
  - `llm.js` — `callLLM({ systemPrompt, userPrompt, schema })` — Google Gemini 2.0 Flash client, JSON-Schema → Gemini `responseSchema` translation.
  - `supabaseAdmin.js` — `createAdminClient()` factory that throws on missing env vars.
  - `ats.js` — Greenhouse / Lever / Ashby ATS detector + job poller.
  - `nominatim.js`, `google-places.js`, `logo-dev.js` — third-party API helpers.
  - `enrichers/` — one file per data source: `crunchbase.js`, `utah-dcc.js`, `github.js`, `wappalyzer.js`, `producthunt.js`, `news.js`. Each exports an `enrichFrom*` function returning a partial record.

**Quality Gate (Onboarding-specific):**
- Purpose: Decide whether a freshly enriched record auto-publishes or queues for human review.
- Location: `supabase/functions/onboard-company/quality-gate.js`, `supabase/functions/onboard-company/utah-bounds.js`, `supabase/functions/onboard-company/prompts.js`
- 4 ordered checks (first failure short-circuits): required-fields → Utah bounding box → duplicate detection → DCC active status.

**Persistence Layer (Postgres):**
- Purpose: Source of truth. RLS enforces access control directly at the DB.
- Location: Schema defined in `supabase/migrations/*.sql` (applied manually).
- Key tables (all `map_` prefixed):
  - `map_startups` — published companies (public read).
  - `map_startup_submissions` — submission queue with `status` ∈ `pending|approved|rejected|auto_published` (admin-gated read/update).
  - `map_admin_users` — email allow-list (authenticated select only).
  - `refresh_log` — audit log for `refresh-jobs` runs (service-role only).
- Indexes: B-tree on common filter facets (`sector`, `stage`, `region`), GIN on `investors` array.
- Extensions: `pg_cron` + `pg_net` for scheduled `refresh-jobs` invocation (see `supabase/migrations/0004_pg_cron.sql`).

## Data Flow

**Flow 1 — Public Map Browse:**

1. User navigates to `/` → `MapView.vue` mounted.
2. `onMounted` calls `useStartupsStore.fetchAll()` if `companies` is empty.
3. Store does `supabase.from('map_startups').select('*')` → bypasses RLS as anon (allowed by `map_startups_public_select` policy).
4. `filteredCompanies` computed by intersecting `companies` with `useFiltersStore` state.
5. `UtahMap.vue` renders pins (`CompanyPin.vue` / `PinCluster.vue`); `CompanyDrawer.vue` opens on `selectCompany(id)`.

**Flow 2 — Public Startup Submission (the "wow" feature):**

1. User pastes URL into `SubmitView.vue` → `SubmitForm.vue` emits.
2. `useOnboarding().submit({ url, email })` calls `supabase.functions.invoke('onboard-company', { body })`.
3. Edge Function (`onboard-company/index.js`):
   a. Validates input.
   b. Creates service-role Supabase client.
   c. Runs `runEnrichmentPipeline` → fetches homepage → calls 6 enrichers in parallel via `Promise.allSettled` → polls ATS → fills gaps via Gemini → geocodes via Nominatim → returns normalized 20-field record.
   d. Runs `runQualityGate(record, supabaseClient)`.
   e. **Pass:** insert into `map_startups` + audit row in `map_startup_submissions` with `status='auto_published'`. Return `{ status: 'auto_published', startup_id, company }`.
   f. **Fail (duplicate):** insert audit row, return `{ status: 'auto_published', existing_id, duplicate: true }`.
   g. **Fail (other):** insert pending row with `status='pending'` + `rejection_reason`, return `{ status: 'pending', reason, company }`.
4. Frontend `SubmitView.vue` switches between `running` / `result` views; `MIN_RUNNING_MS = 8000` ensures progress animation always renders.

**Flow 3 — Admin Sign-In + Review:**

1. User visits `/admin/dashboard` → `adminGuard` (in `goed/src/router/guards.js`) runs.
2. Guard checks `supabase.auth.getSession()`; no session → redirect to `/admin/login`.
3. Guard verifies `session.user.email` exists in `map_admin_users`; missing → `signOut()` + redirect with `?reason=not-allowed`.
4. On `/admin/login`, user submits email → `signInWithMagicLink` → `supabase.auth.signInWithOtp({ email, options: { emailRedirectTo: '/admin/dashboard' } })`.
5. After magic-link click, `useAdminAuth` module-level `onAuthStateChange` listener updates `session`; `watchEffect` re-checks `map_admin_users` and sets `adminVerified`.
6. `AdminLogin.vue` watches `isAdmin` and `router.replace({ name: 'AdminDashboard' })` once true.

**Flow 4 — Weekly Job Refresh (cron):**

1. `pg_cron` job `refresh-jobs-weekly` (Mondays 06:00 UTC, set up manually per `0004_pg_cron.sql`) calls `net.http_post` to `/functions/v1/refresh-jobs` with service-role bearer token.
2. Edge Function selects all `map_startups` with `jobs_refreshed_at IS NULL OR < now()-7d`.
3. For each, calls `pollAts(careers_url)`. On success, updates `job_titles`, `is_hiring`, `careers_url`, `jobs_refreshed_at`.
4. Writes one summary row to `refresh_log` with `source='cron'`.

**State Management:**
- All cross-component state lives in Pinia stores (`goed/src/stores/`).
- Stores own all Supabase reads and writes for their domain (`startups.js` owns `map_startups`, `admin.js` owns `map_startup_submissions`).
- Composables wrap async/auth flows but don't own persistent state (except module-level singletons in `useAdminAuth` and `useLogoDev`).
- No URL-state sync yet (filters store has stub `syncFromUrl`/`syncToUrl` pending Feature 0002).

## Error Handling

**Strategy:** Defensive — never let a single failed enricher or third-party API kill an end-to-end flow. Errors are logged to `console.error` with module-prefix tags (`[pipeline]`, `[onboard-company]`, `[refresh-jobs]`) and either swallowed (best-effort enrichment) or returned to the caller as structured JSON.

**Patterns:**

- **Enrichment pipeline** (`supabase/functions/_shared/pipeline.js`): Every external call is wrapped in its own `try/catch`. The 6 parallel enrichers run via `Promise.allSettled`; rejected ones log but don't propagate. The pipeline never throws — always returns a 20-key record (with nulls for fields it couldn't fill).

- **Edge Functions**: Outer `try/catch` returns `errorResponse('INTERNAL_ERROR', 'Unexpected failure', 500)` with structured `{ error, code }` JSON. Inner steps with their own failure modes (e.g. duplicate audit insert) log non-fatally and continue.

- **Frontend stores**: Try/catch around Supabase calls; on failure set `error.value = err`, return `{ data: null, error: err }`, and ensure `isLoading.value = false` in `finally`. See `useAdminStore.fetchSubmissions` in `goed/src/stores/admin.js`.

- **Frontend composables**: Same pattern with explicit `result`/`status`/`error` refs. `useOnboarding` additionally enforces a minimum delay so the UI never flickers on instant errors.

- **Quality gate failures** are not errors — they return `{ passed: false, reason }` and the function still responds 200 with `{ status: 'pending', reason, company }`.

- **CORS preflight** is short-circuited at the top of every Edge Function with `if (req.method === 'OPTIONS') return new Response('ok', { headers: corsHeaders })`.

- **Method guard**: Non-POST returns 405 with `errorResponse('INVALID_INPUT', 'Only POST is supported', 405)`.

- **JSON parse errors**: Caught and returned as 400 `INVALID_INPUT`.

## Cross-Cutting Concerns

**Logging:**
- Backend: `console.error` with `[function-name]` prefix tags. Persistent audit logging only for `refresh-jobs` → `refresh_log` table via `logRun(...)`.
- Frontend: No structured logger. Errors surface to user via reactive `error` refs in stores/composables.

**Validation:**
- Edge Functions: Manual type/shape checks on inputs (URL via `new URL(...)`, string types). No schema library.
- Quality gate: `requiredFields = ['name', 'address', 'sector', 'description']` enforced before publish (in `supabase/functions/onboard-company/quality-gate.js`).
- Frontend: Native HTML `<input required type="email">`. No client-side schema library.
- Database: `CHECK` constraints on enum-like columns (`status`, `source`).

**Authentication:**
- Frontend: Supabase magic-link OTP via `supabase.auth.signInWithOtp` (`goed/src/composables/useAdminAuth.js`).
- Authorization: Two-layer allow-list against `map_admin_users` — client-side in `adminGuard` (`goed/src/router/guards.js`) AND DB-side in RLS policies (`auth.jwt() ->> 'email' IN (SELECT email FROM map_admin_users)`, see `supabase/migrations/0006_admin_users.sql`).
- Edge Functions: Public endpoints (`onboard-company`) accept anon key; privileged endpoints (`refresh-jobs`) require service-role JWT.
- Service-role client is constructed only inside Edge Functions via `createAdminClient()`; the service-role key is never shipped to the browser.

**CORS:**
- Inlined `corsHeaders` const per Edge Function. `Access-Control-Allow-Origin: '*'` for both `onboard-company` and `refresh-jobs`. Identical OPTIONS-handler boilerplate.

**Configuration / Secrets:**
- Frontend: `import.meta.env.VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_LOGO_DEV_TOKEN` (Vite env vars, baked at build time).
- Edge Functions: `Deno.env.get('SUPABASE_URL')`, `'SUPABASE_SERVICE_ROLE_KEY'`, `'GOOGLE_AI_API_KEY'`, plus per-enricher API keys. Never committed.

**Caching:**
- Frontend `useLogoDev` memoizes per-domain in a module-level `Map`.
- No HTTP caching configured beyond Vite/Netlify defaults.
- Database: pg_cron + `jobs_refreshed_at` recency gate (7 days) acts as a refresh cache for ATS data.

**Performance:**
- Client-side filtering of the small (~96-row) `map_startups` dataset; no server-side pagination.
- Map clustering kicks in at zoom < `CLUSTER_THRESHOLD = 7` (`goed/src/components/map/UtahMap.vue`).
- Enrichment pipeline parallelizes the 6 source enrichers via `Promise.allSettled`.
- Homepage HTML truncated to 50 KB before being passed to the LLM.
