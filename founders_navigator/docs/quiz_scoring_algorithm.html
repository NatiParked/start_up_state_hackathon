Quiz scoring algorithm

The three quiz questions (answers determine match)
Question 1: What stage is your company?
Answers: Pre-revenue | Early revenue | Scaling | Established
Maps to: Communities field in data (Student, Rural, Women, Veteran, Multicultural, New American)
Question 2: What's your industry?
Answers: Software/IT | Healthcare | Manufacturing | Agriculture | Hospitality/Food | Other
Maps directly to: Industries field in data
Question 3: What do you need most right now?
Answers: Funding | Talent/hiring | Community | Legal/compliance | Marketing
Maps directly to: Topics field in data
Scoring: How resources get ranked (pseudocode)
// For each resource in database: score = 0 // EXACT MATCH on Industries (highest weight) if (resource.Industries.includes(userIndustry)) { score += 100 } // EXACT MATCH on Topics (high weight) if (resource.Topics.includes(userTopic)) { score += 80 } // Communities match (medium weight) // Map user stage to Communities field const stageToCommunitiesMap = { "Pre-revenue": ["Student"], "Early revenue": ["Student", "Multicultural", "New American"], "Scaling": ["Women", "Veteran"], "Established": ["Any"] // matches everything } if (resource.Communities.any(c => stageToCommunitiesMap[userStage].includes(c))) { score += 40 } // Location match (light weight) if (resource.Locations includes userCounty) { score += 20 } // Diversity bonus (slight boost) if (resource.Communities includes "Women" || "Minority" || "Veteran") { score += 5 } // Sort all resources by score DESC // Return top 15 resources
Match type Points Rationale
Industry match (exact) +100 Most specific. A software company needs software resources.
Topic match (exact) +80 User explicitly asked for this (Funding, Talent, etc.)
Communities match (stage-based) +40 Pre-revenue founders need student resources; scaling needs mentor resources
Location match +20 Nice-to-have. In-state resources are better but not critical.
Diversity bonus +5 Light boost for inclusive programs (women, veteran, multicultural)
Stage → Communities mapping (critical)
User stage Maps to Communities Reasoning
Pre-revenue Student, Rural, Multicultural, New American Early founders often in school or underserved communities. Focus on learning + exploration.
Early revenue Student, Multicultural, New American, Women Getting traction. Include student because bootstrapped founders. Include underserved + women (strong Utah cohorts).
Scaling Women, Veteran, (any) Mature founders need mentor networks + advanced resources. Inclusive programs more relevant.
Established (Any community) Match everything. Established companies benefit from broad ecosystem access.
Edge cases & handling
What if no exact industry match?
→ Give +50 for "Other" industry category. Then boost Topics score. A software company in "Other" industry still gets high rank if they need Funding.
What if multiple topics match?
→ Add +80 for EACH matching topic. E.g. resource has both "Funding" and "Marketing" and user asked for "Funding" → they get +80 for that match, but +0 for the Marketing (doesn't apply to this user).
What if resource has no Communities field (empty)?
→ Skip the Communities match (+0). No penalty. This resource is "for everyone," so it still appears if Industries/Topics match.
What if user is out-of-state?
→ No location penalty. But in-state resources float to top (via +20 location bonus). Out-of-state still rank high if industry/topic are perfect matches.
Ties (two resources, same score)?
→ Secondary sort: alphabetical by title. Deterministic.

Scoring function (clean code template)
function scoreResource(resource, userStage, userIndustry, userTopic) { let score = 0; if (resource.industries.includes(userIndustry)) score += 100; if (resource.topics.includes(userTopic)) score += 80; if (stageMatch(userStage, resource.communities)) score += 40; if (resource.locations.includes(userLocation)) score += 20; if (hasDiversityTag(resource.communities)) score += 5; return score; }
Special case: "Skip" button
If user clicks skip on Q1
→ Show all 100 resources, sorted by default order (ID or alphabetical). No scoring applied. User can then search/filter manually.
If user clicks skip on Q2
→ Fall back to "null" industry. Scoring still applies for Stage + Topic. Returns top 15 resources that match Stage + Topic, regardless of industry.
If user clicks skip on Q3
→ Fall back to "null" topic. Scoring applies for Stage + Industry. Returns top 15 resources that match Stage + Industry.
